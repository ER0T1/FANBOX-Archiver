# FANBOX Archiver 後續開發規劃

更新日期：2026-10-29

適用版本：v1.3.2 起

這是專案唯一的產品開發規劃。已完成版本的功能紀錄以 `README.md` 為準；實作規則以根目錄 `AGENTS.md` 為準。完成、取消或被取代的規劃不再另外保存，避免多份文件狀態互相矛盾。

## 1. 現況基線

v1.3.1 已完成原定 GUI 轉型主線：

- 保留 Python CLI、`serve`、`index` 與 `open`，不破壞既有封存格式。
- 動態本機閱讀器直接查詢 SQLite 與封存 JSON，下載後不必重建索引。
- GUI 已涵蓋投稿、Creator Profile、Fan Card、備份、工作歷史、封存驗證及安全設定。
- 前端已拆分為 TypeScript 模組，編譯成單一 `core.js` 隨 Python wheel 與桌面版發布。
- Tauri 2 Windows 桌面程式可管理 PyInstaller sidecar、首次啟動封存選擇、切換封存及啟動失敗復原。
- 備份與驗證共用後端單工作佇列；工作與事件持久化至 SQLite，重啟後會將未完成工作標示為 `interrupted`。
- NSIS 已通過同版覆蓋、`1.2.0 → 1.3.0`、`1.3.0 → 1.3.1`、解除安裝、登錄清理及外部封存資料保留測試。
- Windows CI、版本一致性檢查、正式簽章建置腳本及 GitHub Release 工作流程已建立。

上述項目視為維護範圍，不再另立「重做 GUI」或「將 Python 核心全面改寫為 TypeScript」的計畫。

## 2. 持續遵守的架構原則

1. **本機優先**：GUI 與 API 預設只監聽 `127.0.0.1`，Cookie、投稿和設定不得上傳至遠端服務。
2. **CLI 必須保留**：桌面 GUI、瀏覽器 GUI 與 CLI 共用相同 Application Layer、設定與 SQLite schema。
3. **保守存取 FANBOX**：維持循序下載、請求間隔、權限錯誤停止及嚴格來源白名單，不繞過付費牆、CAPTCHA 或反自動化機制。
4. **封存不可破壞**：schema migration 前建立備份；版本發布、設定修改及桌面升級不得刪除使用者封存。
5. **以量測決定重寫**：Python 下載核心目前不是使用者操作瓶頸；沒有 profiling 證據前不改寫為 TypeScript、Rust 或其他語言。
6. **動態閱讀為主、靜態匯出為輔**：日常 GUI 不要求執行 `index`；靜態網站保留作為可攜式匯出功能。

## 3. 優先工作

### P0：正式 Windows 發布就緒

目前開發版安裝器仍未簽章。程式碼管線已完成，但正式公開散發前必須完成外部憑證配置。

工作項目：

- 取得有效 Windows code-signing PFX 憑證。
- 在 GitHub 設定 `WINDOWS_CERTIFICATE`、`WINDOWS_CERTIFICATE_PASSWORD` 與時間戳服務。
- 以 `vMAJOR.MINOR.PATCH` tag 執行一次完整正式發布，確認 Authenticode 狀態為 `Valid`。
- 在乾淨的 Windows 11 x64 環境驗證安裝、首次啟動、升級、解除安裝與 SmartScreen 體驗。
- 核對 GitHub Release 同時包含簽章安裝器及 `SHA256SUMS.txt`。
- 保存上一版安裝器，讓每次發布都執行真實跨版本升級測試。

完成標準：正式 Release 不接受未簽章檔案；簽章、時間戳、雜湊及跨版本升級全部可驗證。

### P1：GUI 工作狀態與設定一致性

後端已保證備份與封存驗證不能同時執行，工作期間修改設定也會回傳 `409`。剩餘工作是讓 GUI 在使用者點擊前就呈現相同限制。

工作項目：

- 將全域 active job 狀態傳入備份、維護與設定頁。
- 任一工作執行時停用「開始備份」、「開始驗證」及「儲存設定」，並顯示目前工作的類型與狀態。
- 工作完成、失敗或取消後自動恢復控制項，不要求重新整理頁面。
- 保留 API 的單工作鎖與 `409` 防線，不能只依賴前端停用按鈕。
- 增加 E2E：備份執行時維護與設定不可提交；驗證執行時備份不可開始。

後續可選設計：允許工作執行期間先保存「下一次工作使用」的設定。若實作，執行中的工作必須持有不可變設定快照，且 GUI 要清楚標示生效時機；在此之前維持禁止修改較安全。

完成標準：畫面限制與後端規則一致，不會先允許操作再以錯誤訊息補救。

### P1：影片投稿備份支援

模型已預留 `video` 資源類型，但尚未取得有權存取的實際 FANBOX 影片投稿樣本，因此禁止猜測 API 或媒體網址。

工作項目：

- 取得至少一份已去除帳號憑證的真實投稿 JSON／HTML fixture，確認影片是 FANBOX 原生檔案、外部嵌入或串流播放清單。
- 擴充 structured parser 與 HTML fallback，保留標題、說明、封面、原始順序和可合法取得的媒體資訊。
- 只有在 FANBOX 直接提供可下載原始資源且目前帳號有權存取時才下載；第三方 iframe 僅保存安全連結卡片。
- 為檔名、MIME、續傳、SHA-256、失敗重試與完整性驗證增加測試。
- 動態 Reader 與靜態匯出需提供一致的影片或安全外部連結顯示。

完成標準：fixture、解析、保存、Reader、靜態匯出與驗證測試完整，且不擴大現有安全白名單。

### P2：FANBOX 介面變更回歸防護

FANBOX 沒有穩定公開 API，解析器維護會是長期工作。

工作項目：

- 新增去識別化 fixture 時，同時記錄取得日期、投稿類型及預期資源數量。
- 對 Creator Profile、article、image、file、text、embed、Fan Card 與未來 video 建立參數化回歸測試。
- API payload 缺少欄位時要產生可理解的警告；不可默默把預覽圖當原圖。
- 在狀態頁或診斷輸出中顯示 parser／schema／應用程式版本，方便回報相容性問題。
- 文件化 fixture 更新流程，確保不提交 Cookie、交易資料或其他私人內容。

完成標準：FANBOX 結構改變時，CI 能以明確 fixture 差異或錯誤指出受影響的內容類型。

### P2：可觀測性與效能量測

目前沒有證據顯示更換核心語言能改善主要使用者體驗；先建立可重複量測。

工作項目：

- 建立 1,000 篇投稿的去識別化合成資料集，量測首頁、搜尋、創作者分頁及單篇 Reader。
- 記錄 API 查詢、JSON 讀取、縮圖／封面載入及前端渲染的個別耗時。
- 為 SQLite 常用查詢執行 `EXPLAIN QUERY PLAN`，只在有量測證據時增加索引。
- 檢查長時間工作事件的資料庫大小與 GUI 輪詢成本，必要時調整事件壓縮與保留策略。
- 將可重現的效能基準放入 CI 的非阻斷工作，穩定後再設定退化門檻。

完成標準：能指出瓶頸位於網路、SQLite、磁碟、Python 還是前端；語言重構必須引用量測結果。

### P3：桌面版操作完善

工作項目：

- 新增「關於／診斷」頁，顯示 GUI、Python sidecar、schema、設定檔與封存位置版本資訊。
- 提供「開啟封存資料夾」與「開啟日誌資料夾」，但不自動開啟或暴露 Cookie。
- 評估簽章穩定後導入 Tauri updater；更新必須可取消、驗證簽章並保留封存資料。
- 增加桌面啟動失敗頁的自動化測試，包括無效設定、無法存取資料夾及 sidecar 提前退出。

完成標準：常見診斷與資料位置操作不需回到 CLI，更新失敗不影響既有版本與封存。

## 4. 建議里程碑

### 里程碑 A：v1.3.x 操作一致性

- 完成 GUI 全域工作鎖狀態。
- 補齊設定、備份、驗證互斥 E2E。
- 完成桌面啟動失敗復原測試。

### 里程碑 B：首個簽章 Windows Release

- 配置正式憑證與 GitHub secrets。
- 在乾淨 Windows 11 驗證簽章安裝器。
- 發布安裝器與 SHA-256 校驗檔。

### 里程碑 C：影片支援

- 取得合法 fixture 後才開始。
- 完成解析、保存、閱讀、匯出及完整性驗證。

### 里程碑 D：長期維護基線

- 完成 parser fixture 規範。
- 建立 1,000 篇資料效能基準。
- 依量測結果決定索引、快取或架構調整。

## 5. 每批開發的完成條件

每一批修改都必須：

- 更新 `README.md` 對應版本紀錄。
- PATCH 版本加 1，並同步 Python、Rust、Tauri 與 lockfile。
- 執行 `npm run release:check` 及與變更範圍相稱的 Python、Node、Rust、E2E 或安裝器測試。
- 不降低 CLI 相容性、安全白名單、封存原子性或資料保留保證。
- 依 `AGENTS.md` 建立本機 Git commit；除非使用者明確要求，不推送、不建立 tag、不發布 Release。

## 6. 明確不做

- 不建立多使用者 SaaS 或公開網路服務。
- 不把 Cookie、投稿、設定或封存上傳至遠端。
- 不繞過 FANBOX 權限、付費牆、CAPTCHA 或反自動化限制。
- 不提高下載並行度來追求速度。
- 不解壓或執行第三方附件。
- 不移除 CLI、`index` 或既有 archive 格式。
- 不在缺乏效能證據時重寫 Python 核心。
